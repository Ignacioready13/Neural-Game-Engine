1. WHY THIS DATASET LOOKS DIFFERENT FROM THE PILOT
--------------------------------------------------------------------------------
Findings from Stage 4 that shape this stage:
  - The key capability is steering response to a click. The signal is tiny in the next
    frame and only shows up over about 10 frames, so the model must see MANY clean
    examples of click ONSETS (and retargets) in situations where the choice is
    visually meaningful: two reachable doors on opposite sides of screen center, both
    reasonably near. The pilot had few such contexts (the validation split had 15
    episodes and about 30 usable counterfactual contexts, far too few for reliable
    statistics).
  - Turn directions in the pilot were imbalanced (about 42.5% positive vs 57.5%
    negative signed heading changes). The engine's door positions are left/right
    balanced (about 48.5/51.5), so the imbalance seems to come from bot behavior.
    Mirror augmentation will handle residual imbalance in training, but the data should
    be as balanced as the bots can make it.
  - The one-step learning curve was flat, so more frames of the same walking add little.
    What helps is diversity (distinct episodes, rooms, hallways) and coverage of rare
    events (choices, onsets, retargets, doorway reveals). Frames within an episode are
    highly redundant; distinct episodes count more than raw frame count.
  - Validation and test must be big enough to evaluate action-following with real
    statistics (hundreds of qualifying contexts from many distinct episodes).
Facts for planning (measured earlier on this machine): generation ran at about 523
frames/s with concurrency 8; PNG frames average about 80.5 KB; a 600-frame episode is
about 48 MB; the pilot packed at 96x72 is 1.83 GB per 88k frames (about 21 KB per
frame) and at 64x48 about 9 KB per frame; the sidecar is about 60 MB per 88k frames;
the machine has about 30 GiB of RAM and (as of Stage 2) about 569 GB of free disk. The
engine's clipping failsafe aborted about 3.3% of pilot episodes.

    packer), outside git tracking.

3. WORK
--------------------------------------------------------------------------------
3.1 Pre-flight
  Check free disk and that the engine's tests and typecheck pass as they did at the end
  of Stage 2 (do not fix unrelated problems; report them). Read the pilot's recorded
  seed ranges. Estimate the bulk's PNG and packed sizes from the numbers above and
  confirm the disk limits in rule 8(ii). Nothing else should be using the GPU during
  generation.

3.2 Trial, one tuning round, then fix the mixture
  The qualifying-context definition is the one implemented in neural/probe_click.py:
  an accepted-click onset window with two reachable doors on opposite sides of screen
  center, with near and far doors reported separately (reuse that code, do not
  reimplement it). Count it per split and per 1,000 frames.
  a. Trial: generate a small trial (about 60 episodes, current "mixture" profile, seeds
     in a scratch range that will be discarded or excluded from bulk_v1), pack it to a
     scratch location, and measure: persona frame shares; the rate of qualifying
     near-door onset contexts per 1,000 frames; the left/right balance of signed
     heading changes and of click-resolved turn directions; the abort share; the share of
     frames with actionHasClicked false. Also compute the same numbers on the pilot, so
     we have a baseline for comparison.
  b. Tune ONCE. Create a new named profile (for example "mixture_v2") that raises the
     yield of qualifying near-door onsets and balances direction, aiming at roughly 2x
     the pilot's yield without breaking the rest. Likely levers: more weight on the
     choice-triggered personas (decisive, dither, prober) and less on idle and uniform;
     shorter reaction delays so choices happen while both doors are still near; and a
     check that choosing among candidates is not biased by their sorted order or
     tie-breaking. Constraints: every persona keeps at least about 3% of frames, the
     never-clicked regime and the stale-held-click regime stay represented, and the
     abort share stays below about 5%. If a bot-side bug is causing the left/right
     imbalance, fix it in the bot code (without changing the existing profiles'
     behavior for the pilot). If the cause is in the engine's world generation (for
     example bends or doors only generated one way), do NOT change it; this is rule 8(iv).
     Target balance: signed heading changes within about 47-53% either way.
  c. Confirm with a second small trial (about 30 episodes) that the new profile meets the
     targets. Do not iterate further; if targets are partly missed, proceed with the
     best profile and record the numbers.

3.3 Size the splits and run the bulk
  - Using the measured yield, set validation and test so that each has at least about
    400 qualifying near-door onset contexts drawn from at least 100 distinct episodes
    (cap each at about 250 episodes). Train gets about 1,100 episodes. If the plan
    would exceed the disk limits, raise rule 8(ii).
  - Write the plan (explicit seed ranges recorded in it, profile mixture_v2, 600 frames
    per episode, concurrency 8) and run it with the existing resumable plan runner.
    If it is interrupted, resume it. Watch the aborted share; the engine's alert
    thresholds apply, and rule 8(iii) triggers at about 10%.
  - Run the existing diagnostics report on the finished dataset.

3.4 Pack
  Pack bulk_v1 at 96x72 and 64x48 with the Stage 3 packer (incremental, deterministic).
  Confirm the packed totals match the manifests (frames, viewUnsafe frames, episodes by
  split). Run the existing loader tests against the bulk packed set, and measure loader
  throughput on it with the default memory-mapped mode (96x72, K = 4); note that the
  full set at 96x72 is on the order of 17 GB, so do not assume it fits in RAM.

--------------------------------------------------------------------------------
Write neural/docs/STAGE4B-REPORT.md (technical; the user will have me translate it). It
must contain, for the pilot and for bulk_v1 side by side where applicable:
  1. Dataset size: episodes and frames per split, PNG bytes, packed bytes at both

  6. Integrity: seed disjointness (within bulk_v1 and against the pilot), incomplete
     episodes, the manifests' engine source hash and config hash, the packed totals
